**Source:** Codex (`gpt-5.4`, hostile review) + Claude synthesis, run against `chore/skills-updates` branch HEAD.
**Scope:** Full repo as a template — CLAUDE.md, `.claude/skills/*`, `.claude/agents/*`, `justfile`, `.github/workflows/*`, `devops/*`, `scripts/*`, backend + frontend source, instruction/ docs.

## Bottom Line

**CLAUDE.md is NOT sufficient as a single source of truth for Claude in a copied project.**

Copying this template into a new project today produces landmines inside the first 10 minutes:
- Renamed backend package whose tests still import the old name
- `.env.example` that crashes settings parsing
- Skills that try to spawn a nonexistent `read-only` subagent type
- CLAUDE.md `Standard Commands` list citing just recipes that don't exist
- `instruction/templates/4-frontend-engineer.md` recommending a totally different frontend stack than the one scaffolded

Not shippable as-is.

## P1 — Significant gaps

### Template lifecycle
- `scripts/template_clean.py` writes `.template-cleaned` — removes nothing. `README.md` + `CLAUDE.md:63` both claim it removes example code. **Lifecycle theater.** `scripts/template_clean.py:6`

### Backend correctness
- Middleware order documented "RequestID → SizeLimit → CORS outermost-first" is wrong in code. A 413 response has NO `X-Request-ID` header (empirically confirmed). `CLAUDE.md:484` and `instruction/reference/FASTAPI_PATTERNS.md:9` teach the wrong pattern. `projects/backend/package/main.py:115-120`
- `RequestSizeLimit` middleware trusts `Content-Length` only — chunked/no-length bypasses the advertised 1 MB cap. `projects/backend/package/main.py:51`
- `/ready` returns ready unconditionally — no DB/cache/migration/dep check. Teaches a production anti-pattern. `projects/backend/package/api/health.py:11`
- Plain-string `logger.info(...)` everywhere; `instruction/templates/6-devops-deployment.md:41` demands structured JSON. Zero logging config in the template. `projects/backend/package/main.py:18,86`

### Instruction vs reality
- `.claude/skills/dev-cycle/SKILL.md:97` and `.claude/agents/code-fixer.md:25` say "don't touch tests" — directly contradicts mandatory TDD in `CLAUDE.md:83`.
- `.claude/skills/simplify/SKILL.md:89` says extract shared utilities by default; `CLAUDE.md:313` says extract only when helper ROI is positive. Claude fights itself.
- `instruction/templates/3-backend-engineer.md` demonstrates f-string logging (line 160), bare `except Exception` (line 187), and returns bare `dict` (line 214) — every one of these is banned by the Python Style section in `CLAUDE.md`. "Good pattern" examples violate the rules.
- `instruction/templates/4-frontend-engineer.md:31` recommends **Next 14 + Shadcn + Radix + Zustand + React Hook Form** — actual scaffold is **Next 15 + MUI + React Query**. Claude will invent the wrong stack if it reads this file.

### Frontend demo teaches wrong patterns
- Generated Orval client never checks `res.ok` — 4xx/5xx HTTP responses flow through as "success" data. `BackendHealthSection`'s error state cannot catch HTTP errors. `projects/frontend/src/lib/generated/endpoints.ts:52,539`
- Orval-generated echo **mutation** hook exists at `endpoints.ts:597`, but `TemplateSetupForm.tsx:19` uses fake local state — template fails to demonstrate React Query mutation + invalidation.
- No client-side error boundary component anywhere in the Next.js app.

### CI / pre-commit drift
- `devops/.pre-commit-config.yaml:45` runs `pnpm run prettify` (prettier **--write**). `just lint` via pre-commit **mutates files** — lint is a writer, not a check.
- CI does NOT match pre-commit. `.github/workflows/ci.yml:76` runs only the sys.path custom hook; pre-commit also enforces `no-future-annotations` and `no-type-checking-blocks` (`devops/.pre-commit-config.yaml:64,70`). "CI-equivalent" is false.
- `.gitignore:58` ignores `uv.lock`, but CI runs `uv sync`. Dependency resolution is non-reproducible across copied projects.
- GitHub Actions are tag-pinned (`@v4`), not SHA-pinned. `.github/workflows/ci.yml:16,19,24`
- Codex path in `CLAUDE.md:409` is `~/node_modules/.bin/codex` — doesn't exist on common install paths. Use `codex` from `PATH` instead.

### Backend dependencies missing for a "shipping" project
No auth, no DB, no migrations, no rate limiting, no structured logging, no observability. Acceptable for a toy; incompatible with the "runnable full-stack template with CI" claim in `README.md:7` and the CRUD/auth coverage discussion in `CLAUDE.md:538`.
